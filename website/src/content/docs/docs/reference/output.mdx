`mailgrail build` writes three files per template. For a template named
`"confirm-email"` with the default EJS engine:

```
dist/emails/
  confirm-email.ejs     full HTML with placeholders
  confirm-email.js      the render function
  confirm-email.d.ts    the parameter types
```

The template file's extension follows `templatingEngine` — `.ejs`, `.hbs` or
`.mustache`.

## The template file

Written for reading and debugging. Nothing imports it at run time: the
generated `.js` inlines the same string, so the compiled module has no
dependency on the file sitting beside it. You can delete it from a deployment
and everything still works.

## `.d.ts` — the types

```ts title="dist/emails/confirm-email.d.ts"
export type ConfirmEmailParams = {
  username: string;
  confirmationUrl: string;
};

export declare function renderConfirmEmail(params: ConfirmEmailParams): {
  name: "confirm-email";
  sender: string;
  subject: string;
  text: string;
  html: string;
};
```

Parameters declared with `t.optional` or `t.default` appear here as optional
properties — `nickname?: string` — so the call site knows exactly what it may
leave out.

## `.js` — the render function

```js title="dist/emails/confirm-email.js"
import ejs from "ejs";

const htmlTemplate = "<!doctype html>…";

function normalizeParams(params) {
  // every declared key filled in, defaults applied
}

export function renderConfirmEmail(input) {
  const params = normalizeParams(input);

  return {
    name: "confirm-email",
    sender: "hello@example.com",
    subject: ejs.render("Welcome, <%- username %>!", params),
    text: ejs.render("Welcome, <%- username %>! …", params),
    html: ejs.render(htmlTemplate, params),
  };
}
```

Two things worth noticing. The only import is your engine — no React, no MJML,
no bundler, no mailgrail. And the input is normalized before it reaches the
engine, which is what makes a missing optional render as nothing instead of
throwing.

## Using it from a backend

```ts
import { renderConfirmEmail } from "./dist/emails/confirm-email.js";
import nodemailer from "nodemailer";

const email = renderConfirmEmail({
  username: "Alice",
  confirmationUrl: "https://example.com/confirm?token=abc123",
});

await transporter.sendMail({
  from: email.sender,
  to: "alice@example.com",
  subject: email.subject,
  text: email.text,
  html: email.html,
});
```

## Commit it, or build it

Both work.

**Commit the output** and your deployment needs no build step for email, and
you can see in a diff exactly how a template change alters the rendered HTML —
which is a genuinely useful review artifact. Add a CI check that it is current.

**Build it in CI** and you carry no generated files in review. Run
`mailgrail build` before packaging, and make sure your engine is a real
dependency rather than a dev one.

## Turning off types

Set `typescript: false` and the `.d.ts` is not emitted. The `.js` is written
either way — it is the artifact that matters.
