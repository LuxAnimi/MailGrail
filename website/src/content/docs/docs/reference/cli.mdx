MailGrail installs a single binary with two commands. Both read your
`mailgrail.config.ts` and both accept `--configPath`.

<CliCommands />

## Running it

With the scripts the scaffold adds:

```sh
npm run preview-emails
npm run build-emails
```

Or directly, without adding scripts:

```sh
npx mailgrail preview
npx mailgrail build
```

## In CI

`mailgrail build` is the only command you need in a pipeline. It exits non-zero
when a template fails to compile or the configured engine is missing, so a
broken template fails the build rather than reaching production:

```yaml
- run: npm ci
- run: npx mailgrail build
```

If you commit the compiled output rather than generating it at deploy time, add
a check that it is current — the same idea as a lockfile. There is a subtlety to
getting that check right, so it lives with the rest of the decision in
[wiring it into your build](/MailGrail/docs/getting-started/build-integration).
