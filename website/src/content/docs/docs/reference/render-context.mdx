Every template function receives a render context — `mg` — instead of raw
parameters. That indirection is what lets MailGrail see which parameters you
used and emit the matching placeholders, rather than substituting values it
would then have to reverse-engineer.

```tsx
const htmlTemplate = (mg: RenderTemplateContext<Params>): ReactElement => (
  <MjmlText>Welcome, {mg.render("username")}!</MjmlText>
);
```

:::note[Every example below is executed]
The compiled output and the rendered result are produced by running MailGrail's
real compiler when this page is built. Generation fails unless the preview
context and all three engines produce byte-identical output for each example,
so these pages are also an integration test.
:::

:::tip[Paths are typed]
Every path argument is checked against your schema. TypeScript errors on a path
that does not exist, and on the wrong method for a type — `mg.each` on a
non-array, `mg.when` on a number.
:::

## `mg.each(path, (item, index) => …)`

For an array of scalars the item context has a single no-argument `render`.

<LiveProof id="each-primitives" />

For an array of objects the item is a full context scoped to the element, so
`render`, `when`, `unless`, `each` and `with` all work on it.

<LiveProof id="each-objects" />

Arrays of arrays nest the same way — the outer item exposes `each` directly:

```tsx
mg.each("schedule", (day) =>
  day.each((slot) => (
    <MjmlText>
      {slot.render("time")}: {slot.render("event")}
    </MjmlText>
  )),
);
```

## Subjects and text bodies

`subjectTemplate` and `textTemplate` take the same context, typed
`TextTemplateContext<Params>`. The only difference is what it composes: the
helpers and their callbacks return strings rather than markup.

```ts
const textTemplate = (mg: TextTemplateContext<Params>): string =>
  `Hi ${mg.render("username")}` +
  mg.each("items", (item) => `\n- ${item.render("name")}`) +
  mg.when("isPro", () => "\n\nThanks for subscribing.", () => "");
```

Values are not escaped there — a plain-text body wants `&`, not `&amp;` — and
newlines survive into the output on all three engines.

What you cannot do is transform a value the context hands back.
`mg.render("total")` is a placeholder the engine fills in when the email is
sent, so `.toFixed(2)` has nothing to work on. The build fails rather than ship
the mangled placeholder; pass the value in already formatted instead.

## Why not just pass the values?

The context emits opaque tokens rather than engine syntax directly, and the
real syntax is substituted at the very end. That is not indirection for its own
sake: the compiled HTML passes through React and then MJML, and both transform
text. React escapes `<% %>` into `&lt;% %&gt;`, and MJML drops bare text
sitting between structural components outright. Tokens survive both stages, so
the placeholders arrive intact.

It is also why block helpers return React nodes: their children render through
React normally instead of being flattened with `String()`.
