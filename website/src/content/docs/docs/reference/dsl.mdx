Use `t.*` to describe the shape of a template's parameters. MailGrail reads
that schema at build time to generate TypeScript types, and at preview time to
generate placeholder data.

```ts
import { t } from "@luxanimi/mailgrail";
import type { Infer } from "@luxanimi/mailgrail/dsl";

const paramsSchema = t.object({
  username: t.string(),
});

type Params = Infer<typeof paramsSchema>;
```

:::note[Generated, not transcribed]
The inferred types below come from `emitObjectType` — the same function that
writes the `.d.ts` your backend imports — and the placeholders from the same
compiler that produces your templates. They are generated when this page is
built, so they cannot drift from what MailGrail actually emits.
:::

## Missing values never throw

The generated module normalizes its input before rendering: every declared key
is filled in, `t.default` values are applied, and an absent optional becomes an
empty string.

That normalization is not a nicety. Without it the three engines disagree:
EJS raises a `ReferenceError` on a missing key, while Handlebars and Mustache
silently render nothing. Normalizing first means the same parameters produce
the same email whichever engine you compile to.
