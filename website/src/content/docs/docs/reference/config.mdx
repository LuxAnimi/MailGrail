MailGrail reads a `mailgrail.config.ts` from your project root. Every field is
optional; the defaults below are the ones the resolver actually applies.

```ts title="mailgrail.config.ts"
import { defineConfig } from "@luxanimi/mailgrail";

export default defineConfig({
  sourceDir: "emails-src",
  outputDir: "emails-dist",
  typescript: true,
  previewPort: 7777,
  templatingEngine: "EJS",
});
```

`defineConfig` is an identity function that exists purely for the types — it
gives you completion and checking in the config file without any runtime cost.

## Paths

`sourceDir` and `outputDir` are both resolved **relative to the config file**,
not to the working directory. That means `mailgrail build` behaves the same
whether you run it from the project root or from a workspace package.

## Choosing a different location

Both commands take `--configPath` if your config is not at the default
location:

```sh
mailgrail build --configPath ./config/mailgrail.config.ts
```

See the [CLI reference](/MailGrail/docs/reference/cli).
