A template is a plain object exported from a `.tsx` file. It declares its
parameters, an HTML template, a subject line, and a plain-text fallback.

## 1. Declare the parameters

```tsx title="emails/ConfirmEmail.tsx"
import { t } from "@luxanimi/mailgrail";
import type { Infer } from "@luxanimi/mailgrail/dsl";

const paramsSchema = t.object({
  username: t.string(),
  confirmationUrl: t.string(),
});

type Params = Infer<typeof paramsSchema>;
```

`Infer` turns the schema into the TypeScript type, so `Params` here is
`{ username: string; confirmationUrl: string }`. You never write that type by
hand, and it cannot fall out of step with the schema.

## 2. Write the markup

```tsx title="emails/ConfirmEmail.tsx"
import type { ReactElement } from "react";
import { MjmlColumn, MjmlText, MjmlButton } from "@faire/mjml-react";
import type { RenderTemplateContext } from "@luxanimi/mailgrail";
import BaseLayout from "./components/BaseLayout";

const htmlTemplate = (mg: RenderTemplateContext<Params>): ReactElement => (
  <BaseLayout>
    <MjmlColumn>
      <MjmlText>Welcome, {mg.render("username")}!</MjmlText>
      <MjmlButton href={mg.render("confirmationUrl")}>
        Confirm your account
      </MjmlButton>
    </MjmlColumn>
  </BaseLayout>
);
```

The function receives a **render context** (`mg`) rather than raw parameters.
That is what lets MailGrail track which parameters you used and emit the right
placeholders — see the
[render context reference](/MailGrail/docs/reference/render-context).

:::note
`BaseLayout` already wraps its children in an `MjmlSection`, so start directly
with `MjmlColumn` inside it.
:::

## 3. Write the subject and text

These receive the same kind of context as the markup, composing strings rather
than elements — they are compiled to templates too:

```tsx title="emails/ConfirmEmail.tsx"
import type { TextTemplateContext } from "@luxanimi/mailgrail";

const subjectTemplate = (mg: TextTemplateContext<Params>): string =>
  `Welcome, ${mg.render("username")}!`;

const textTemplate = (mg: TextTemplateContext<Params>): string =>
  `Welcome, ${mg.render("username")}! Confirm your account: ${mg.render(
    "confirmationUrl",
  )}`;
```

Branch with `mg.when` and iterate with `mg.each`, exactly as in the markup. A
plain `if` here would pick its branch once, at build time, for every recipient.

A plain-text part is not optional in practice. Some clients prefer it, some
spam filters expect it, and it is what shows in a notification preview.

## 4. Export the definition

```tsx title="emails/ConfirmEmail.tsx"
import type { TemplateDefinition } from "@luxanimi/mailgrail";

export const ConfirmEmail: TemplateDefinition<typeof paramsSchema> = {
  name: "confirm-email",
  sender: "hello@example.com",
  params: paramsSchema,
  htmlTemplate,
  subjectTemplate,
  textTemplate,
};
```

`name` decides the output filenames and the exported render function:
`confirm-email` gives you `confirm-email.js` exporting `renderConfirmEmail`.

## 6. Preview it

```sh
npx mailgrail preview
# → http://localhost:7777
```

Every template appears in the sidebar, rendered with placeholder data derived
from its schema. Edit a file and the preview reloads.

## 7. Compile it

```sh
npx mailgrail build
```

Three files land in your `outputDir`, and
[the output](/MailGrail/docs/reference/output) is what your backend imports.

Nothing runs that command for you yet. Deciding what does — and whether the
